# 微信公众号文章导入 Obsidian（首版）设计

## 仓库结构约定

- 本插件作为当前项目的一个子插件开发
- 代码与配置位于：obsidian-plugins/wechat-clipper/

## 目标

- 在 Obsidian 内通过粘贴公众号文章 URL，一键导入为 Markdown 笔记
- 提炼正文文本与图片，图片下载到本地并在笔记中以相对路径引用
- 尽可能移除末尾与知识沉淀无关的引导内容（打赏、关注、推荐阅读等）

## 非目标

- 不支持需要微信登录态才能访问的文章
- 不追求覆盖所有非标准结构文章，首版以公开可访问文章的稳定导入为主
- 不提供浏览器扩展/脚本联动入口（仅 Obsidian 内粘贴 URL）

## 用户体验

### 入口

- 命令面板：Import WeChat Article from URL
- 输入：文章 URL
- 输出：在 Vault 中创建一篇新笔记并下载引用图片

### 默认落盘位置

- 笔记目录：inbox/wechat/
- 图片目录：assets/wechat/

### 文件命名

- 默认：<标题>.md
- 重名处理：若同名文件已存在，则追加 -YYYY-MM-DD
  - 优先使用文章发布时间（若可解析）
  - 否则使用导入当天日期

## 数据流与模块

1. 解析与校验 URL
2. 请求文章 HTML
3. DOM 解析与正文抽取
4. 清洗与裁剪（移除无关区域、末尾截断）
5. HTML → Markdown 转换
6. 图片收集、下载与本地化引用替换
7. 写入 Markdown 到 Vault
8. 汇总结果提示（成功/失败、失败图片数量等）

## 抓取与解析策略

### 抓取

- 使用 Obsidian 插件运行环境内的 HTTP 请求能力直接拉取 HTML
- 请求头策略
  - Referer：文章 URL
  - User-Agent：常见桌面浏览器 UA

### 正文抽取

- 主路径：以 #js_content 为正文容器
- 备用路径：当主路径不存在时，尝试常见候选容器（以配置化列表维护）
- 抽取范围仅限定在正文容器内，避免头部导航、侧边栏与脚注污染

## 无关内容清理

### DOM 级移除

- 在正文容器内优先移除常见无关模块的节点（如赞赏、二维码、关注提示、相关推荐、分享组件等）
- 以可维护的选择器列表实现

### 末尾截断兜底

- 从正文末尾向前查找触发关键词块，一旦命中则从该块起整体丢弃
- 默认关键词（可配置）
  - 赞赏
  - 打赏
  - 推荐阅读
  - 阅读原文
  - 长按识别二维码
  - 关注公众号
  - 更多精彩内容

## Markdown 生成

### Frontmatter（可用则写入）

- source：文章 URL
- title：文章标题
- author：作者名（若可解析）
- account：公众号名称（若可解析）
- publish_time：发布时间（若可解析）

### 内容结构

- 保留常见块结构：标题、段落、列表、引用、代码块
- 统一处理多余空行与不可见字符

## 图片本地化

### 图片 URL 提取

- 优先：img[data-src]
- 回退：img[src]

### 下载与引用替换

- 逐张下载到 assets/wechat/<笔记文件名安全片段>/
- 在 Markdown 中替换为相对路径引用
- 对单张失败图片保留原始 URL 占位，并在导入完成后提示失败数量

## 错误处理与可观测性

- URL 不合法：提示并终止
- 抓取失败：提示 HTTP 错误信息并终止
- 正文抽取失败：提示“未找到正文容器”并终止
- 图片部分失败：笔记仍生成，提示失败数量与可选的重试入口

## 安全与隐私

- 不记录或上传用户数据与文章内容
- 不要求提供 Cookie，不引导用户填入登录态信息
- 请求仅访问用户提供的 URL

## 验收与测试

### 样本集

- 收集 10-20 篇公开可访问文章作为回归样本
- 覆盖不同账号、不同排版、含多图/长文/多级标题等情况

### 验收标准

- 正文可读性：段落与标题结构基本正确
- 图片完整性：绝大多数图片可下载并本地引用不丢失
- 清理效果：末尾引导内容被清理且不明显误删正文
